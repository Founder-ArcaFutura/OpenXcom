# Preregistered permutation aggregation probe

Five recorded February-June decision states; explicit descriptions of existing rewards only (factorial condition 0000). No reward buffs, saturation, training, native changes, quotas, campaign rollout or API calls. The same checkpoint and CPU runtime remain in use.

Five arms per state: canonical, reversed and fixed seeded single-order controls from the factorial, and two permutation-mean PLAN arms. Targets retain original order and current risk context. Twenty-five portfolios total, but the component inference count is larger and reported separately with cache/automatic decisions.

Family A contains all cyclic rotations of canonical action IDs. Family B starts from a deterministic shuffled ordering outside A's cyclic orbit, then uses all its rotations. Each family presents every eligible action, including SAVE, once in every position. Family B's fixed tag is permutation-holdout-2903; it is not selected after observing outcomes. With one/two actions the families coincide and are not independent tests; otherwise their ordered-packet sets are disjoint for identical options. Family B is a separate family-sensitivity check, not held-out campaign evidence or all permutations of n options.

Average the checkpoint's returned choice probabilities by action ID, then select the largest mean; exact ties break by sorted stable ID. Probabilities are uncalibrated model scores, not success odds or expected utility. SAVE remains a normal eligible action. Record every component packet, score vector, vote, mean and margin. A low margin is descriptive only; no new abstention threshold is introduced. Automatic singleton choices need no model inference.

Primary comparison: A/B exact portfolio and mission-mix agreement, first PLAN agreement, complete deferral and spend. The within-family invariance from using the same full set of rotations is mathematical, not a claimed empirical result. Report target-order limitations, divergent branches, input-limit failures and underlying component vote disagreement. More missions, diversity or spending is not by itself better strategy.

Exact-packet caches include state, ordered criteria and instructions. Prior receipts require matching checkpoint/model/planner fingerprints. Reused decisions are not independent inference. Original source hashes and live code are checked unchanged. These are five fixed snapshots from one campaign; no alternative earlier outcomes are propagated into later states. Direct bases and funded assaults remain unavailable under the supplied states/rules.

Also report agreement of unordered mission-region sets alongside exact execution-order agreement: equal selected operations in a different creation order are distinct from choosing different operations. Native creation order can still affect subsequent mission RNG.
